# SourceSnapshot 与只读工具契约（R1 首片）

## 1. 决策与状态边界

依照统一 Agent 执行方案 §18，先实现合成样本和本地只读项目输入。CLI 的 `project` 命令不创建 Run、不调用模型、不执行构建，不需要 PostgreSQL。本地 manifest 只描述内容寻址的快照产物，不保存 Agent 计划、审批、预算恢复点等业务状态；后续 Run 的权威业务状态仍使用 PostgreSQL。现有离线 Mission/Approval 不是本工具的执行票据，历史迁移保持不变。

这不是完整 R1。真实模型、统一主循环、Run 恢复、AST、漏洞发现、Patch Workspace 和隔离验证尚未交付。合成样本的标注是测试预期，不是分析器已经证明的结论。

## 2. 权限与信任

1. `project import --source` 是调用者明确选择的本地读取范围，`--snapshot` 是唯一的新目录写入范围。源目录与目标不能相同、嵌套或通过别名交叉；目标父目录必须已存在且受调用者控制。现有目标不能覆盖。
2. 导入不等于允许向模型发送数据、运行 Maven/Gradle/脚本、修改原项目或发布产物。所有查询仅在快照范围内读取。
3. 仓库文件名、README、注释、POM、工具输出均是不可信数据，不能改变策略。命令输出为 JSON，不将源码解释为命令。
4. 默认排除敏感路径、密钥和构建产物，返回排除原因，但不读取被排除内容。文件名规则不能检测所有嵌入源码的秘密；导入成功不是脱敏认证，仍不得据此自动授权模型外发。

## 3. 完整性与平台安全

- 使用根目录句柄和平台无跟随检查，不用字符串前缀判断作为访问边界。Windows 仅支持本地 NTFS，使用相对句柄并拒绝 reparse point/junction；Linux 要求支持 `openat2` 和 `statx` Mount ID 的内核（5.8+）及允许的本地文件系统，使用 `BENEATH | NO_SYMLINKS | NO_XDEV`，不向旧式有竞态的访问回退。同设备但不同挂载 ID 的源/目标父配置会保守拒绝，以避免 bind 别名隐藏物理嵌套。特殊文件、不安全链接、网络/FUSE 和无法可靠判断的边界失败关闭。支持范围以平台实现与实际测试结果为准，不声称支持所有操作系统和文件系统。
- `os.Root` 自身会跟随树内链接，不阻止设备、proc 或 bind mount；不能将其称作沙箱。导入器必须额外检查，无法安全支持的配置应拒绝。
- 清单保存文件路径、大小、内容 SHA-256、来源、策略版本、排除项与覆盖限制。没有可靠 commit 则留空，不隐式执行 Git 或推断提交。
- 导入返回 `snapshot_hash`。**调用者必须在快照目录之外可信保存摘要**，并通过每次查询的 `--snapshot-hash` 提供。攻击者可以同时替换目录内的 manifest 和 hash，因此“目录内 hash 自证完整”没有可信意义。
- 读取必须校验清单及相应文件内容；未列文件不能被工具读取。快照文件变化不得自动被视为原证据。文件大小、编码或完整性异常应报告，不得忽略后继续声称完整。
- “只读”是应用层契约，不是 OS 级不可变，也不是对同 UID/管理员或能修改快照和外部可信摘要的攻击者的隔离。Linux 要求新目标父目录的属主/写权限可安全支持；按句柄校验后执行删除仍不宣称能对抗同 UID 的恶意改名竞态。导入读取多个文件，不保证源树的原子时间点一致性；导入期间应停止修改源目录，检测到变化应失败。
- 不修改源文件内容；普通读取可能由文件系统更新访问时间，不承诺所有源目录元数据完全不变。

## 4. 工具契约

| CLI | 工具 | 行为与证据 | 副作用 |
|---|---|---|---|
| `project import` | 快照导入 | 新目录、固定清单和摘要；资源不足/取消不返回成功快照 | 仅独占新目标目录 |
| `project inspect` | `inspect_project` | 从允许清单获得 Java/POM/源码根目录等结构线索 | 无 |
| `project list` | `list_files` | 稳定排序的允许文件，含文件摘要与大小 | 无 |
| `project read` | `read_source` | 完整性校验后的源码行、相对路径、行号和文件摘要 | 无 |
| `project search` | `search_source` | 大小写敏感字面量逐行检索，不运行正则或外部程序 | 无 |

查询默认每页 50 项，最多 200 项。整体 JSON 输出、单行、搜索工作量另有硬限制；达到限制必须通过 `partial`、限制原因、`truncated` 或后续游标表达，不静默截断。游标绑定快照、工具和查询参数，不是可提权的授权凭证。`--start-line` 仅用于首次读取，不与游标组合；后续页保持相同查询与 limit。

项目识别仅提供结构线索：多个 `pom.xml` 不等于 Maven 模块关系已解析；未执行 Maven，不声称得到有效依赖图、SBOM、调用图或漏洞确认。非 UTF-8、二进制等不支持输入要明确报告，搜索未覆盖的文件不得被当作没有匹配。

## 5. 错误、资源与重复调用

- 非法参数、策略拒绝、完整性失败、超限、取消和 I/O 错误须明确返回；CLI 错误退出非零，不输出成功结果。
- 查询是只读操作，可在相同可信摘要上重复调用；没有对补丁、构建或网络执行的幂等承诺，因为本片没有这些能力。
- 导入只创建不存在的新目标，重复导入到同一目标失败；失败仅允许清理明确属于本次创建的产物，不能删除既有目录。
- 导入固定上限：10,000 文件、20,000 遍历条目、16 MiB 单文件、128 MiB 总内容、32 层深度、8 MiB 清单、最多记录 1,000 条排除原因；不能靠参数无限放宽。达到限制必须失败或明确 partial，不能返回虚假的完整覆盖。搜索每次最多扫描 256 文件/16 MiB，使用游标继续；整体查询 JSON 最多 256 KiB。
- 所有路径检查与限额在确定性 Go 代码内执行，不依赖模型判断。安全测试与资源上限见包内测试；平台专项跳过必须在验收报告中保留，不能算作已验证。

## 6. 验收方法

1. 单元和 CLI 集成测试在 `t.TempDir()` 内创建样本和目标；不连接数据库、不运行 Maven、不调用模型。
2. 比较源文件内容；检索正/负/未知标注对应的片段，但不据检索结果宣称漏洞成立。
3. 测试目录边界、链接、敏感排除、资源限制、完整性篡改、分页和取消。Windows/Linux 分别验证平台安全实现。
4. 后续端到端路线见 `java-fixture-acceptance.md`。基线安全失败、补丁后通过、业务不退化只能在批准的隔离测试执行后认领，不能由本片的快照测试替代。
